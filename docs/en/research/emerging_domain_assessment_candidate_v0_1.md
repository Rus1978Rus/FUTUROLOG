# EMERGING_DOMAIN_ASSESSMENT_CANDIDATE v0.1
## Candidate mode for assessing emerging domains

**Status:** `ADAPT / REFERENCE / LATER / NOT_CORE / NOT_OBJECTIVE_FORMULA / NOT_VALIDATED`

**Source:** user-provided archive `OKComputer_Философы_и_математики.zip`, especially `зерно_и_формула.md`, `SPEC.md`, and `seed_formula.py`.

## Source-supported structure

The source proposes a seven-stage logical map:

```text
1. Verbalization of the question
2. Definition
3. Idealization
4. Symbolization
5. Measurement
6. Axiomatization
7. Algorithmization
```

The source explicitly states that this is a logical order rather than a mandatory chronological law. Real trajectories may reorder stages, loop back, or stall.

`seed_formula.py` contains `TransformationEngine.diagnose`, which estimates the current formalization frontier, passed/missing stages, and a candidate next step. This is useful as a donor mechanism for domains that are still pre-technological.

## Protective invariants

```text
MEASUREMENT != CONSTRUCT_VALIDITY
FORMALIZATION != UNDERSTANDING
FORMALIZATION_PROGRESS != REALITY_COVERAGE
```

## What is not imported

`SPEC.md` assigns starting values `formality=0.05`, `meaning=1.0`, heuristic `formality_delta` / `meaning_delta`, and a crisis boost of `×1.5` on the next formalization step.

These values are classified as:

```text
NOT_CALIBRATED
NOT_EMPIRICALLY_VALIDATED
NOT_OBJECTIVE_SCORE
NOT_FORECAST_PROBABILITY
```

They may only serve as an experimental harness until separate calibration and falsification protocols exist.

## Boundary with Objective / Coverage

```text
DOMAIN_FORMALIZATION_STAGE
!=
EVIDENCE_COVERAGE
```

A domain can be highly formalized while evidence for a specific forecast is weak; a poorly formalized field can still contain strong observed facts.
