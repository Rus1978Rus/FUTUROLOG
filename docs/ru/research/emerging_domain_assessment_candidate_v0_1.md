# EMERGING_DOMAIN_ASSESSMENT_CANDIDATE v0.1
## Кандидатный режим диагностики зарождающихся областей

**Статус:** `ADAPT / REFERENCE / LATER / NOT_CORE / NOT_OBJECTIVE_FORMULA / NOT_VALIDATED`

**Источник:** пользовательский архив `OKComputer_Философы_и_математики.zip`, прежде всего `зерно_и_формула.md`, `SPEC.md`, `seed_formula.py`.

## Что поддерживает источник

Источник предлагает семистадийную логическую карту превращения вопроса в формализованную конструкцию:

```text
1. Вербализация вопроса
2. Определение
3. Идеализация
4. Символизация
5. Измерение
6. Аксиоматизация
7. Алгоритмизация
```

Сам источник отдельно оговаривает, что это **логический порядок, а не хронологический закон**. Реальные траектории могут менять порядок этапов, возвращаться назад и застревать.

В `seed_formula.py` есть `TransformationEngine.diagnose`, который пытается определить фронтир формализации, пройденные/непройденные этапы и недостающий следующий шаг. Это полезный донорский механизм для диагностики областей, которые ещё не дошли до готовой технологии.

## Что берём в FUTUROLOG

Кандидатный режим должен отвечать не «правда ли теория», а:

```text
насколько устойчиво определён вопрос?
очерчен ли объект?
есть ли идеализация?
есть ли рабочая символика?
появилось ли измерение?
есть ли явные правила/аксиомы?
есть ли повторяемый алгоритм?
```

Потенциальный владелец:

`Emerging Domain Assessment / Emerging Domain Radar`.

Это будущий прикладной режим для horizon scanning (сканирования горизонта), weak signals (слабых сигналов), ранних научно-технологических направлений и pre-technology maturity (дотехнологической зрелости).

## Защитные инварианты

```text
MEASUREMENT != CONSTRUCT_VALIDITY
FORMALIZATION != UNDERSTANDING
FORMALIZATION_PROGRESS != REALITY_COVERAGE
```

По-русски:

- наличие измерения не доказывает, что измеряемая конструкция валидна;
- рост формальности не равен росту понимания;
- прогресс формализации не доказывает полноту охвата реальности.

## Что НЕ берём

`SPEC.md` прямо задаёт стартовые `formality=0.05`, `meaning=1.0`, эвристические `formality_delta` / `meaning_delta`, а кризис в симуляции усиливает следующий прирост формальности в `×1.5`.

Эти числа:

```text
NOT_CALIBRATED
NOT_EMPIRICALLY_VALIDATED
NOT_OBJECTIVE_SCORE
NOT_FORECAST_PROBABILITY
```

Они могут использоваться только как экспериментальный harness (полигон) для сравнения поведения модели, пока не появится отдельная калибровка и falsification protocol (протокол опровержения/проверки).

## Граница с Objective / Coverage

Этот кандидатный слой не должен подменять текущий Objective/Coverage redesign.

```text
DOMAIN_FORMALIZATION_STAGE
!=
EVIDENCE_COVERAGE
```

Например, область может иметь алгоритмы и развитый формальный аппарат, но слабую доказательную базу по конкретному прогнозу. И наоборот, по малоформализованной области могут существовать сильные наблюдаемые факты.

## Решение v0.1

```text
DONOR_DECISION: ADAPT / REFERENCE
TARGET: Emerging Domain Assessment
RUNTIME_CORE: NO
OBJECTIVE_FORMULA: NO
CURRENT_IMPLEMENTATION: NO
VALIDATION: NO
```

Порядок разработки FUTUROLOG не меняется. Следующий технический шаг остаётся `OBJECTIVE_COVERAGE_FORMULA_BAKEOFF_v0_1`. Этот кандидат возвращается после стабилизации универсального ядра и Objective/Coverage.
