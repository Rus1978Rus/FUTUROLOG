"""
Centralized configuration constants for Entropy-RG v3.6.2.

Single source of truth for default values used across:
- scoring core;
- objective aggregator;
- security / SYSTEM_META;
- API schema defaults.

M3.6.2 does not change the M3.6.1 scoring formula.
It only controls whether Objective Layer may activate and which
alpha value is used at runtime.
"""

from __future__ import annotations

import os


OBJECTIVE_LAYER_ENABLED_DEFAULT = False

DEFAULT_ALPHA = 0.5
ALPHA_WEEK_1 = 0.5
ALPHA_WEEK_2 = 0.4
ALPHA_CANONICAL = 0.3

DEFAULT_GAMMA = 0.07

UNIVERSAL_WEIGHTS_VERSION = "preprint-v1-uncalibrated"
OBJECTIVE_WEIGHTS_VERSION = "objective-mvp-v1-uncalibrated"

MODEL_VERSION = "entropy-rg-v3.6.2-objective-ready"
CALIBRATION_STATUS = "uncalibrated"


def parse_bool(value: str | bool | None, default: bool = False) -> bool:
    if value is None:
        return default

    if isinstance(value, bool):
        return value

    normalized = str(value).strip().lower()
    if normalized in ("true", "1", "yes", "on", "y"):
        return True
    if normalized in ("false", "0", "no", "off", "n"):
        return False

    return default


def is_objective_layer_enabled() -> bool:
    """
    Read the global Objective Layer rollout flag.

    Environment:
        ENTROPY_RG_OBJECTIVE_LAYER_ENABLED=true/false

    Default:
        False, because rollout must be explicitly enabled.
    """
    raw = os.environ.get("ENTROPY_RG_OBJECTIVE_LAYER_ENABLED")
    return parse_bool(raw, default=OBJECTIVE_LAYER_ENABLED_DEFAULT)


def get_active_alpha() -> float:
    """
    Read alpha from environment if set, otherwise return DEFAULT_ALPHA.

    Environment:
        ENTROPY_RG_ALPHA=float in [0, 1]

    Recommended rollout:
        week 1 after activation: 0.5
        week 2 after activation: 0.4
        canonical after observation: 0.3

    The schedule is operator-controlled. No hardcoded calendar dates.
    """
    raw = os.environ.get("ENTROPY_RG_ALPHA")
    if raw is None:
        return DEFAULT_ALPHA

    try:
        value = float(raw)
    except (TypeError, ValueError):
        return DEFAULT_ALPHA

    if 0.0 <= value <= 1.0:
        return value

    return DEFAULT_ALPHA


def get_weights_version() -> dict[str, str]:
    return {
        "universal": UNIVERSAL_WEIGHTS_VERSION,
        "objective": OBJECTIVE_WEIGHTS_VERSION,
    }


def get_system_meta_config() -> dict:
    """
    Shared metadata source for healthcheck/security/API response builders.
    """
    return {
        "model_version": MODEL_VERSION,
        "weights_version": get_weights_version(),
        "calibration_status": CALIBRATION_STATUS,
        "alpha": get_active_alpha(),
        "gamma": DEFAULT_GAMMA,
        "objective_layer_enabled": is_objective_layer_enabled(),
    }
```

## 9. FAQ

### Why is Objective Layer disabled by default?

Because v3.6 changes `final_score` when active. Safe rollout requires the
operator to enable the layer explicitly.

### Why alpha starts at 0.5 instead of 0.3?

0.5 is a conservative activation value. It reduces the initial effect of
Objective Layer until behavior is observed. The canonical target remains 0.3.

### Why is weights_version now an object?

Universal and Objective weights will be calibrated independently. A single
string cannot express that cleanly.

### Does final_score always change in v3.6?

No. If Objective Layer is disabled or inactive, `final_score = universal_risk`.

### What if only two objective components are present?

Objective Layer remains inactive. At least three active components are required,
and `scale_stability` must be one of them.

### Is this calibrated?

No. `calibration_status = "uncalibrated"`. M5 will introduce calibration.

## 5. TECHNICAL_SPECIFICATION.md — Objective Layer section rewrite

```markdown
# Objective Layer

Status: active as controlled rollout in v3.6.2.

## 1. Two-layer scoring model

Entropy-RG v3.6.2 uses a two-layer ERG-CAD scoring model:

```text
final_score =
    universal_raw × (alpha + (1 − alpha) × objective_risk_or_1)
    − gamma × trust_adjustment
```

Where:

```text
objective_risk_or_1 =
    objective_risk if Objective Layer is active
    1.0 otherwise
```

This guarantees backward-compatible behavior when Objective Layer is
disabled or inactive.

## 2. Universal Layer

Universal Layer measures intensity of the risk signal.

Implemented components:

| Component | Weight | Status |
|---|---:|---|
| gibbs | 0.25 | building block |
| rg_persistence_score | 0.22 | ready |
| sequential_anomaly_score | 0.18 | ready |
| surprise | 0.18 | building block |
| graph_risk | 0.12 | partial/ready depending on graph context |
| trust_penalty | 0.10 | ready |

Formula:

```text
weighted_base_without_trust =
    sum(universal_weight_i × universal_component_i)

universal_raw =
    weighted_base_without_trust + confluence_bonus

universal_risk =
    universal_raw − gamma × trust_adjustment
```

`universal_risk` is preserved for backward compatibility.

## 3. Objective Layer

Objective Layer measures objectivity of the risk signal.

Implemented components:

| Component | Weight | Meaning |
|---|---:|---|
| scale_stability | 0.25 | persistence across aggregation levels |
| temporal_persistence | 0.20 | persistence across time windows |
| source_redundancy | 0.20 | independent source support |
| observer_agreement | 0.20 | independent detectors agree to flag |
| noise_separation | 0.15 | separation from noise baseline |

Objective component values are in `[0, 1]`.

```text
0 = no objective support
1 = strong objective support
```

## 4. Objective aggregation

A component is active if:

```text
component_result is not None
AND component_result.confidence >= 0.3
```

Objective Layer activates only if:

```text
active_component_count >= 3
AND scale_stability is active
AND objective_layer_enabled = true
```

Weights are normalized over active components:

```text
normalized_weight_i =
    objective_weight_i / sum(objective_weight_j for active j)
```

Then:

```text
objective_risk =
    sum(normalized_weight_i × component_i.value)

objective_confidence =
    sum(normalized_weight_i × component_i.confidence)

objective_layer_partial =
    any(component_i.partial for active components)
```

## 5. Trust adjustment

`trust_adjustment` is a separate modifier.

It is subtracted exactly once:

```text
final_score = ... − gamma × trust_adjustment
```

It is not included in `universal_raw`.

## 6. Final formula

When Objective Layer is active:

```text
final_score =
    universal_raw × (alpha + (1 − alpha) × objective_risk)
    − gamma × trust_adjustment
```

When Objective Layer is disabled or inactive:

```text
final_score =
    universal_raw − gamma × trust_adjustment
    = universal_risk
```

## 7. Config controls

Environment variables:

```bash
ENTROPY_RG_OBJECTIVE_LAYER_ENABLED=false
ENTROPY_RG_ALPHA=0.5
```

Default:

```text

```

Alpha rollout:

```text

```

```markdown
# Baseline Policy

## 1. Purpose

Baselines protect Entropy-RG from accidental scoring changes.

Any change to scoring math must either:
- preserve the relevant baseline; or
- intentionally create a new baseline with a documented reason.

## 2. Baseline types

### M1.4 no-objective baseline

Purpose:

```text
Verify backward-compatible scoring when Objective Layer is inactive.
```

Expected:

```text
final_score == universal_risk
objective_layer_active == false
```

Pytest marker:

```python
@pytest.mark.baseline_no_objective
```

This baseline must remain valid after v3.6.2.

### M3.6.1 full-objective baseline

Purpose:

```text
Verify scoring when Objective Layer is enabled and active.
```

Required config:

```bash
ENTROPY_RG_OBJECTIVE_LAYER_ENABLED=true
ENTROPY_RG_ALPHA=0.5
```

Pytest marker:

```python
@pytest.mark.baseline_full_objective
```

This baseline becomes the reference for Objective Layer behavior until M5.

## 3. Future baselines

M5 calibration will create:

```text
calibrated_v1_baseline
```

Old baselines are not deleted. They are marked legacy and kept for regression.

## 4. When to create a new baseline

Create a new baseline only when:

- scoring formula changes;
- weights change;
- calibration changes;
- alpha/gamma policy changes;
- component semantics change.

Do not create a new baseline for:

- docs updates;
- refactoring with no score change;
- API field additions that do not affect scoring.

## 5. Required baseline checks

Every release must run:

```bash
pytest -m baseline_no_objective -v
pytest -m baseline_full_objective -v
```

For releases before Objective Layer activation, full-objective baseline may be absent.
After v3.6.2, both are required.
```

## 9. Риски

## Risk 1: config flag читается неконсистентно

Detection:
- `test_objective_layer_disabled_by_default`
- `test_objective_layer_enabled_via_env`

Mitigation:
- single source of truth in `app/config.py`;
- all modules import `is_objective_layer_enabled()`.

## Risk 2: alpha schedule переключён в production без audit trail

Detection:
- deployment config diff;
- runtime metadata check.

Mitigation:
- response and SYSTEM_META include `alpha`;
- M8 dashboard / M9 audit can log alpha changes later.

## Risk 3: weights_version object ломает старых клиентов

Detection:
- API compatibility tests;
- migration guide breaking changes section.

Mitigation:
- document as breaking change;
- clients must update parsing logic.

## Risk 4: ENV bool parsing edge cases

Detection:
- tests for `true`, `TRUE`, `1`, `yes`, `on`.

Mitigation:
- centralized `parse_bool()`.

## Risk 5: ENV variable absent

Detection:
- `test_objective_layer_disabled_by_default`.

Mitigation:
- default is safe: `False`.

## Risk 6: M3.6.1 baseline stale when alpha changes

Detection:
- full-objective baseline test explicitly sets `ENTROPY_RG_ALPHA=0.5`.

Mitigation:
- baseline policy requires alpha to be fixed for baseline tests.

## Risk 7: rollback not clear

Detection:
- migration guide review.

Mitigation:
- rollback procedure: set `ENTROPY_RG_OBJECTIVE_LAYER_ENABLED=false`.

## Risk 8: tests assume hardcoded alpha

Detection:
- alpha schedule tests.

Mitigation:
- use monkeypatch/env in tests;
- avoid hardcoded alpha outside config.

## Risk 9: composite weights_version not documented as breaking

Detection:
- release notes review.

Mitigation:
- explicit breaking change section in migration guide and release notes.

## Risk 10: HMAC fixtures break due to weights_version schema

Detection:
- HMAC snapshot tests.

Mitigation:
- update fixtures only; do not change HMAC logic.

## Risk 11: objective_layer_enabled disables useful component scores

Potential issue:
- global disable should block activation, not necessarily suppress raw component computation.

Decision:
- In M3.6.2, aggregator returns inactive and does not compute objective_risk.
- Existing component scores may still appear if scoring pipeline computes them before aggregator.
- This is acceptable; `final_score` remains unchanged.

[OPEN_QUESTION] Whether component scores should be omitted when layer is disabled. Recommendation: keep them for observability, but mark layer inactive.
