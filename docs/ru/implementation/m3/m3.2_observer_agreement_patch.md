# Реализация компоненты observer_agreement для Objective Layer

Статус: patch-документ для M3.2  
Проект: «Футуролог»

Основание: `objective_layer_design_v1.md`, `m3_1_temporal_persistence_patch.md`, `futurolog_architecture_v1.1.md`  
Цель: добавить вторую компоненту Objective Layer без активации Objective Layer и без изменения `final_score`

Важно: этот patch-документ подготовлен по архитектурным решениям M3.0–M3.2. Фактический архив `entropy_rg_anomaly_detector_EN_v2_2_FINAL.zip` в текущем контексте не открыт, поэтому места, где требуется сверка с реальным кодом, помечены `[REQUIRES_VERIFICATION]`.

## 1. Сводка

M3.2 добавляет вторую компоненту Objective Layer — `observer_agreement`. Компонента измеряет weighted agreement that the signal should be flagged: насколько независимые observers согласны, что сигнал нужно флагнуть как значимый. Компонента добавляется в `app/objective/observer_agreement.py`, `ObjectiveLayerContext` расширяется полем `observer_results`, а `ObserverResult` получает `reliability: float = 1.0`. Результат возвращается в `objective_component_scores`, но Objective Layer остаётся неактивным: `objective_layer_active = false`, `alpha_active = false`, `objective_risk = null`, а `final_score` должен оставаться численно равным M1.4 baseline. M3.2 не реализует ObserverRegistry, не запускает detectors, не делает I/O и не импортирует `app.scoring` из objective modules.

## 2. Спецификация компоненты

## 2.1 Назначение

`observer_agreement` отвечает на вопрос:

```text
Согласны ли независимые observers, что сигнал должен быть флагнут?
```

Это не абстрактное «согласие вообще». Если все observers согласны, что риска нет, `confidence` может быть высоким, но `value` должен быть низким, потому что Objective Layer интересует подтверждение риска, а не просто консенсус.

Семантика:

```text
value = 0 → никто не флагнул сигнал или weighted support к флагу отсутствует
value = 1 → все observers с ненулевым весом флагнули сигнал
```

Отличие от Universal Layer:

- Universal Layer считает интенсивность сигнала по внутренним компонентам.
- `observer_agreement` агрегирует внешние или независимые результаты detectors, которые ENRA передаёт в Entropy-RG как context.
- Entropy-RG не знает, как observers были запущены, и не реализует эти detectors.

Known MVP observer types:

```python
KNOWN_OBSERVER_TYPES = {
    "rule_detector",
    "graph_detector",
    "sequence_detector",
    "baseline_detector",
    "human_review",
}
```

`human_review` допускается в схеме, но его полноценная интеграция относится к M8/M9. В M3.2 он просто допустимый observer type, если ENRA его передаст.

## 2.2 Интерфейс

```python
def compute_observer_agreement(
    context: ObjectiveLayerContext,
) -> ObjectiveComponentResult | None:
    """
    Compute weighted observer agreement that the signal should be flagged.

    The component reads only context.observer_results and returns:
    - value in [0, 1], where 1 means full weighted agreement to flag;
    - confidence in [0, 1], measuring quality/strength of the measurement;
    - partial=True when observer count is low or observers disagree;
    - reasons describing consensus, disagreement, truncation, unknown types.

    Returns None when:
    - observer_results is empty;
    - all observer weights are zero.

    Does not:
    - activate Objective Layer;
    - change final_score;
    - implement observers or ObserverRegistry;
    - do I/O;
    - import app.scoring.
    """
    ...
```

## 2.3 Формула

Observer weight:

```text
observer_weight_i =
    clip(confidence_i, 0, 1) × clip(reliability_i, 0, 1)
```

Value:

```text
numerator =
    sum(observer_weight_i × 1(flagged_i=True))

denominator =
    sum(observer_weight_i)

value =
    numerator / denominator, если denominator > 0
```

Если:

```text
denominator = 0
```

то:

```text
return None
```

Confidence:

```text
base_confidence_by_count:
    0 observers → 0.0
    1 observer  → 0.3
    2 observers → 0.6
    3+ observers → 0.9

agreement_strength = max(value, 1 - value)

mean_observer_weight = denominator / len(observers)

confidence =
    clip(base_confidence_by_count × agreement_strength × mean_observer_weight, 0, 1)
```

Почему `agreement_strength = max(value, 1 - value)`:

- `value = 1.0`: все флагнули, сильный консенсус, confidence может быть высоким.
- `value = 0.0`: никто не флагнул, тоже сильный консенсус, confidence может быть высоким.
- `value = 0.5`: observers разделились, confidence снижается.

Это ключевое различие:

```text
value = agreement to flag
confidence = quality of the observer measurement
```

## 2.4 Поведение при граничных случаях

### Пустой observer_results

```text
return None
```

Причина: нет observers, значит нечего агрегировать.

### 1 observer

```text
partial = true
base_confidence = 0.3
missing_inputs includes "observer_results.minimum_3"
```

Один observer — это не agreement, а одиночное мнение.

### 2 observers

```text
partial = true
base_confidence = 0.6
missing_inputs includes "observer_results.minimum_3"
```

### 3+ observers

```text
base_confidence = 0.9
partial = false по count
```

Но если `0.3 < value < 0.7`, то:

```text
partial = true
reason = "observer_disagreement"
```

### Все observer_weights = 0

```text
return None
```

Причина: нет usable weight. На уровне aggregator компонент трактуется как missing.

### Unknown observer_type

Unknown observer type не отбрасывается. Добавляется reason:

```text
"unknown_observer_type"
```

Это позволяет ENRA добавлять новые detectors без блокировки Entropy-RG.

### Наводнение observer_results > 100

```python
MAX_OBSERVER_RESULTS = 100
```

Если список длиннее:

- отсортировать по timestamp;
- взять последние 100;
- добавить reason:

```text
observer_results_truncated_to_100
```

### reliability отсутствует

Если поле не передано:

```text
reliability = 1.0
```

Это нужно для MVP, пока ObserverRegistry не ведёт долгую историю reliability.

## 3.2 Новый модуль app/objective/observer_agreement.py

```python
"""
Observer agreement component for Entropy-RG Objective Layer.

This component answers the question:
"Do independent observers agree that the signal should be flagged?"

It measures weighted agreement to flag, not abstract consensus.
All observers saying "no risk" produces low value but may still produce
high confidence, because the measurement itself is consistent.

M3.2 behavior:
- computes ObjectiveComponentResult only when observer_results are present;
- returns None when observer_results are empty or all weights are zero;
- does not activate Objective Layer;
- does not change final_score;
- does not implement observers or ObserverRegistry;
- does not import app.scoring;
- does not do I/O.
"""

from __future__ import annotations

from datetime import datetime, timezone

from app.objective.types import (
    ObjectiveComponentResult,
    ObjectiveLayerContext,
    ObserverResult,
)


MAX_OBSERVER_RESULTS = 100

KNOWN_OBSERVER_TYPES = {
    "rule_detector",
    "graph_detector",
    "sequence_detector",
    "baseline_detector",
    "human_review",
}

BASE_CONFIDENCE_BY_COUNT = {
    0: 0.0,
    1: 0.3,
    2: 0.6,
}

FULL_COUNT_CONFIDENCE = 0.9


def clip_01(value: float) -> float:
    return max(0.0, min(1.0, float(value)))


def parse_timestamp(value: str) -> datetime:
    """
    Parse timestamp for sorting/truncation.

    Invalid timestamps are sorted as oldest by returning datetime.min UTC.
    """
    if not value:
        return datetime.min.replace(tzinfo=timezone.utc)

    try:
        normalized = value.replace("Z", "+00:00")
        parsed = datetime.fromisoformat(normalized)
    except ValueError:
        return datetime.min.replace(tzinfo=timezone.utc)

    if parsed.tzinfo is None:
        parsed = parsed.replace(tzinfo=timezone.utc)

    return parsed.astimezone(timezone.utc)


def observer_weight(observer: ObserverResult) -> float:
    """
    Compute observer weight from current confidence and persistent reliability.
    """
    return clip_01(observer.confidence) * clip_01(observer.reliability)


def base_confidence_for_count(count: int) -> tuple[float, bool]:
    """
    Returns (base_confidence, partial_by_count).
    """
    if count <= 0:
        return 0.0, True
    if count in BASE_CONFIDENCE_BY_COUNT:
        return BASE_CONFIDENCE_BY_COUNT[count], True
    return FULL_COUNT_CONFIDENCE, False


def truncate_observers(
    observers: list[ObserverResult],
) -> tuple[list[ObserverResult], list[str]]:
    reasons: list[str] = []

    if len(observers) <= MAX_OBSERVER_RESULTS:
        return observers, reasons

    sorted_observers = sorted(observers, key=lambda item: parse_timestamp(item.timestamp))
    truncated = sorted_observers[-MAX_OBSERVER_RESULTS:]
    reasons.append(f"observer_results_truncated_to_{MAX_OBSERVER_RESULTS}")
    return truncated, reasons


def reason_about_value(value: float) -> tuple[list[str], bool]:
    """
    Returns (reasons, disagreement_partial).
    """
    reasons: list[str] = []
    disagreement_partial = False

    if value > 0.95:
        reasons.append("all_observers_flagged")
    elif value < 0.05:
        reasons.append("no_observer_flagged")
    elif 0.3 < value < 0.7:
        reasons.append("observer_disagreement")
        disagreement_partial = True
    elif 0.5 <= value <= 0.7:
        reasons.append("weak_majority_flagged")
    elif 0.3 <= value < 0.5:
        reasons.append("weak_majority_not_flagged")

    return reasons, disagreement_partial


def compute_observer_agreement(
    context: ObjectiveLayerContext,
) -> ObjectiveComponentResult | None:
    """
    Compute weighted agreement that observers flag the signal.

    Returns:
        ObjectiveComponentResult or None.

    None means the component is missing and should not contribute
    to objective_risk aggregation.
    """
    if not context.observer_results:
        return None

    observers, reasons = truncate_observers(list(context.observer_results))
    if not observers:
        return None

    total_weight = 0.0
    flagged_weight = 0.0
    unknown_count = 0

    for observer in observers:
        if observer.observer_type not in KNOWN_OBSERVER_TYPES:
            unknown_count += 1

        weight = observer_weight(observer)
        total_weight += weight

        if observer.flagged:
            flagged_weight += weight

    if total_weight <= 0.0:
        return None

    value = clip_01(flagged_weight / total_weight)

    count = len(observers)
    base_confidence, partial = base_confidence_for_count(count)

    agreement_strength = max(value, 1.0 - value)
    mean_observer_weight = total_weight / count

    confidence = clip_01(
        base_confidence * agreement_strength * mean_observer_weight
    )

    value_reasons, disagreement_partial = reason_about_value(value)
    reasons.extend(value_reasons)

    if disagreement_partial:
        partial = True

    if unknown_count > 0:
        reasons.append("unknown_observer_type")
        reasons.append(f"unknown_observer_type_count_{unknown_count}")

    reasons.append(f"observer_count_{count}")

    missing_inputs: list[str] = []
    if count < 3:
        missing_inputs.append("observer_results.minimum_3")

    return ObjectiveComponentResult(
        value=value,
        confidence=confidence,
        missing_inputs=missing_inputs,
        reasons=reasons,
        partial=partial,
    )
```

### Примечания к реализации

- `parse_timestamp` нужен только для truncation.
- Invalid timestamps не ломают расчёт, но сортируются как старые.
- В M3.2 не добавляется reason для invalid timestamp, потому что timestamp не влияет на value. [OPEN_QUESTION] Можно добавить `invalid_observer_timestamp` reason, если это нужно для audit.
- Duplicate `observer_id` в M3.2 не схлопывается автоматически. См. Risk 5.

```markdown
## observer_agreement

Status: implemented in M3.2, informational only.

observer_agreement measures weighted agreement that the signal should be flagged.
It aggregates ObserverResult[] passed by ENRA through ObjectiveLayerContext.

Formula:

observer_weight_i = clip(confidence_i, 0, 1) × clip(reliability_i, 0, 1)

value =
    sum(observer_weight_i × 1(flagged_i=True))
    /
    sum(observer_weight_i)

confidence =
    base_confidence_by_count × max(value, 1 - value) × mean(observer_weight_i)

Known observer types:
- rule_detector
- graph_detector
- sequence_detector
- baseline_detector
- human_review

Unknown observer types are accepted with reason "unknown_observer_type".

observer_agreement does not change final_score in M3.2.
Objective Layer remains inactive until M3.6.
```

## 6. Риски

## Risk 1: integration с integrate_scores меняет final_score

### Что может пойти не так

`observer_agreement` случайно попадёт в weighted_base или final formula.

### Detection

- `test_final_score_unchanged_after_m3_2`;
- сравнение с `tests/fixtures/m1_4_baseline_scores.jsonl`.

### Mitigation

- Передавать observer agreement только в `objective_component_scores`.
- Не менять `final_score`.
- Не менять `universal_risk`.

## Risk 2: confidence формула даёт нелогичный результат при полном отсутствии флагов

### Что может пойти не так

Все observers сказали `flagged=False`. `value = 0`, но это полный консенсус. Если формула confidence ошибочно использует `value` напрямую, confidence станет 0.

### Detection

- `test_none_flagged_value_low` должен проверять `confidence > 0.8`.

### Mitigation

- Использовать `agreement_strength = max(value, 1 - value)`.
- Документировать различие `value` и `confidence`.

## Risk 3: малое число observers + полное согласие даёт завышенный confidence

### Что может пойти не так

Один observer с confidence=1 и reliability=1 даст `value=1`. Без base confidence cap это выглядело бы как сильный consensus.

### Detection

- `test_single_observer_returns_partial_low_confidence`;
- `test_two_observers_returns_partial_medium_confidence`.

### Mitigation

- `base_confidence_by_count`: 1 → 0.3, 2 → 0.6, 3+ → 0.9.
- `partial=True` для 1–2 observers.

## Risk 4: ENRA не передаёт reliability

### Что может пойти не так

Все reliability станут default 1.0. Это может завысить доверие к новым observers.

### Detection

- `test_reliability_default_1_0`;
- audit of response reasons and observer registry.

### Mitigation

- Default 1.0 нужен для backward compatibility.
- В M5 calibration добавить persistent reliability.
- В ENRA docs указать, что reliability should be provided when available.

## Risk 5: дубликаты ObserverResult от одного observer_id

### Что может пойти не так

Один observer может быть передан несколько раз и искусственно усилить свой голос.

### Detection

- Добавить future test `duplicate_observer_id`. [OPEN_QUESTION]
- Log reason when duplicate observer_id detected. [OPEN_QUESTION]

### Mitigation

- M3.2 не схлопывает duplicates по умолчанию, чтобы не терять repeated runs.
- Рекомендуемое решение для M3.3+: deduplicate by latest timestamp per observer_id или require ENRA to pre-aggregate observers. [OPEN_QUESTION]

## Risk 6: timezone в observer.timestamp

### Что может пойти не так

Truncation по timestamp выберет неправильные recent observers, если timestamps в разных форматах.

### Detection

- truncation tests with `Z`, `+00:00`, naive timestamps.

### Mitigation

- `parse_timestamp` нормализует в UTC.
- Invalid timestamps сортируются как oldest.
- Value formula не зависит от timestamp, только truncation.

## Risk 7: смешение human_review с автоматическими detectors

### Что может пойти не так

`human_review` может иметь высокую reliability и перекрыть машинные detectors.

### Detection

- scenario tests with high-reliability human.
- monitor observer weights in debug output. [OPEN_QUESTION]

### Mitigation

- В M3.2 `human_review` просто known type.
- ENRA должна назначать reliability осознанно.
- Full human review loop относится к M8/M9.

## Risk 8: unknown observer types засоряют measurement

### Что может пойти не так

ENRA начнёт присылать произвольные observer types, и они будут влиять на score.

### Detection

- `unknown_observer_type` reason.
- count reason `unknown_observer_type_count_<n>`.

### Mitigation

- Unknown types принимаются для extensibility, но marked in reasons.
- В production можно добавить config: reject_unknown_observer_types. [OPEN_QUESTION]

## Risk 9: observer_results flood

### Что может пойти не так

Слишком длинный список observers замедлит scoring или исказит measurement.

### Detection

- `test_truncation_reason_when_too_many_observers`.
- performance smoke tests.

### Mitigation

- `MAX_OBSERVER_RESULTS = 100`.
- Truncate to most recent observers by timestamp.
- ENRA должна передавать pre-aggregated observer outputs.
